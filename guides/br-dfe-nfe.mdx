## Introduction

An NF-e (_Nota Fiscal Eletrônica_, model 55) is the electronic invoice for goods. The SEFAZ of the issuer's state authorizes it. It is also the document for a consumer sale that an [NFC-e](/guides/br-dfe-nfce) can't cover, and for any return of goods.

Which document to issue, how documents are checked and the environments are in the [DF-e overview](/guides/br-dfe). For onboarding suppliers, see the companion guide: [DF-e supplier registration](/guides/br-dfe-supplier).

## Prerequisites

To issue an NF-e, you will need:

- A registered supplier: follow the [DF-e supplier registration guide](/guides/br-dfe-supplier) to connect the Documentos Fiscais Eletrônicos Brazil app and register the supplier's certificate before issuing.
- Customer details.
- Details of the goods provided:
  - quantity,
  - price, and,
  - applicable tax rates (ICMS, PIS, COFINS, etc.).
- To have chosen an invoice series

## Send invoices

The following examples are of example [GOBL](https://docs.gobl.org) documents you can copy and paste directly into the [Invopop Console](https://console.invopop.com) or store via the API as silo entries. Then, you must run the "DF-e issue product invoice (NF-e)" workflow created during setup over them.

<Info>
The recommended approach for running jobs is to perform two steps: first upload the document to the [silo](/api-ref/silo/entries/create-an-entry-put), then [create a job](/api-ref/transform/jobs/create-a-job-put). In the sandbox, every job attaches the same mock PDF and XML: see [Environments](/guides/br-dfe#environments).
</Info>

<ExampleAccordion />

After authorization, the entry's `data.head.stamps` holds two stamps: `sefaz-key`, the 44-digit access key (_chave de acesso_), and `sefaz-auth`, the authorization protocol number.

### Edge cases

<AccordionGroup>
  <Accordion title="The customer is foreign">
    Identify the customer with a country-qualified `identity`, such as a passport, instead of a `tax_id`. The `identity.country` is an ISO country code other than `BR`.

    - The customer address takes a `country` other than `BR`. GOBL fills it from the identity when you leave it out.
    - The `state` field and the `br-ibge-municipality` extension only apply to Brazilian parties. Leave them out.

    ```json Foreign customer
    "customer": {
      "name": "Acme International Inc.",
      "identities": [
        {
          "key": "passport",
          "country": "US",
          "code": "US-FOREIGN-123"
        }
      ],
      "addresses": [
        {
          "num": "500",
          "street": "Market Street",
          "locality": "San Francisco",
          "code": "94105",
          "country": "US"
        }
      ]
    }
    ```
  </Accordion>
</AccordionGroup>

## Return of an NFC-e

An NFC-e can't cite another document, so it has no credit note (MOC Annex I rule `BA01-10`, rejection `708`). A consumer return is an NF-e entry document that cites the NFC-e. Run it with the "DF-e issue product invoice (NF-e)" workflow.

What changes from the [NFC-e in-person sale](/guides/br-dfe-nfce#in-person-sale):

| Field | Value | Rule |
|---|---|---|
| `$tags` | No `simplified` tag. GOBL sets model `55` | [Model code](https://docs.gobl.org/addons/br-nfe-v4#fiscal-document-model-code) |
| `type` | `credit-note` | |
| `tax.ext.br-nfe-purpose` | `4`, goods return | [`INVOICE-26`](https://docs.gobl.org/addons/br-nfe-v4#validation-rules) |
| `tax.ext.br-nfe-operation-type` | `0`, inbound | [`INVOICE-26`](https://docs.gobl.org/addons/br-nfe-v4#validation-rules) |
| `preceding[0].stamps` | The NFC-e's `sefaz-key` stamp, its 44-digit access key | |
| `customer` | The consumer's CPF, address and IBGE municipality code. An NF-e requires a customer with an address | [`INVOICE-12`, `13`, `22`](https://docs.gobl.org/addons/br-nfe-v4#validation-rules) |
| `lines[].ext.br-nfe-cfop` | `1202`, return of a resale in the same state | [`INVOICE-35`](https://docs.gobl.org/addons/br-nfe-v4#validation-rules) |
| `payment.instructions` | `key: other` with `br-nfe-payment-means` `90`, no payment | [Payment method](https://docs.gobl.org/addons/br-nfe-v4#payment-method) |
| `notes[key=reason].text` | `Devolução de venda ao consumidor` | [`INVOICE-29`, `30`](https://docs.gobl.org/addons/br-nfe-v4#validation-rules) |

```json Changes from the in-person sale
{
  "type": "credit-note",
  "tax": {
    "ext": {
      "br-nfe-presence": "1",
      "br-nfe-purpose": "4",
      "br-nfe-operation-type": "0"
    }
  },
  "preceding": [
    {
      "type": "standard",
      "series": "1",
      "code": "1",
      "issue_date": "2026-10-28",
      "stamps": [
        {
          "prv": "sefaz-key",
          "val": "35261048219376000118650010000000011000000010"
        }
      ]
    }
  ],
  "customer": {
    "name": "Ana Souza",
    "tax_id": {
      "country": "BR",
      "code": "39851726419"
    },
    "addresses": [
      {
        "num": "45",
        "street": "Rua Augusta",
        "locality": "Consolação",
        "state": "SP",
        "code": "01305-000"
      }
    ],
    "ext": {
      "br-ibge-municipality": "3550308"
    }
  },
  "lines": [
    {
      "…": "the lines of the NFC-e",
      "ext": {
        "br-nfe-cfop": "1202"
      }
    }
  ],
  "payment": {
    "instructions": {
      "key": "other",
      "ext": {
        "br-nfe-payment-means": "90"
      }
    }
  },
  "notes": [
    {
      "key": "reason",
      "text": "Devolução de venda ao consumidor"
    }
  ]
}
```

- The return CFOP follows the original sale. `1202` returns a resale bought from third parties. The supplier's tax advisor sets the CFOP for other operations.
- No `br-nfe-credit-note-type` here: it applies to purpose `5` only, as in the [full goods return example](#send-invoices).

<Warning>
An NFC-e credit note fails with `GOBL-BR-NFE-BILL-INVOICE-26`. No GOBL scenario fills its purpose and operation type. Issue the return as an NF-e.
</Warning>

SEFAZ checks that GOBL doesn't run, from the [MOC 7.0 Annex I](https://www.nfe.fazenda.gov.br/portal/exibirArquivo.aspx?conteudo=J%20I%20v4eN00E=):

| MOC rule | Rejection | Check |
|---|---|---|
| `I08-140` | `327` | A goods return takes a return CFOP |
| `I08-20` | `519` | An inbound document can't use a CFOP starting with `5`, `6` or `7` |
| `YA02-04` | `871` | A return takes payment means `90`, no payment |

## Cancel an invoice

Run the "DF-e cancel product invoice (NF-e)" workflow over the silo entry you want to cancel. On success, the entry will be set to `Void`.

The cancel action accepts optional parameters. Set them as a default on the workflow step, in the step's configuration page in the Console. Or pass them as job arguments when [creating the job via the API](/api-ref/transform/jobs/create-a-job-put). Job arguments take precedence over the step configuration.

| Parameter | Job argument | Notes |
|---|---|---|
| Cancellation reason | `nfe-br-cancel-reason` | Free-text reason for the cancellation. At least 15 characters if provided. Defaults to the system default when omitted. |

```json
{
  "workflow_id": "...",
  "silo_entry_id": "...",
  "args": {
    "nfe-br-cancel-reason": "Cancelamento a pedido do Prestador"
  }
}
```
