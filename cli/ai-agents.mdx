The CLI was designed with AI assistants in mind. Because every command is a plain line of text with JSON output, an agent such as [Claude Code](https://claude.com/claude-code) can drive it just as a person would: check an invoice, store it, run a workflow and read the result back.

This is a convenient way to get things done in Invopop without learning the commands yourself. You describe what you want in plain language, and the agent works out which commands to run.

## Why this is safe

The agent never gets a key of its own. It uses the sign-in you created with `invopop auth login`, which means:

- It can only do what **you** are allowed to do in the workspace. If you can't delete something in the Console, neither can the agent.
- It is limited to the workspace you chose as default, unless you ask it to work in another one.
- The access it uses is short-lived and renews itself, so there is no long-lived secret sitting in a file for the agent to copy.

You stay in charge of signing in. The agent cannot complete the browser login for you, and it isn't supposed to ask for the code the browser shows. If it reports that you are not logged in, run the login yourself in your own terminal and try again.

## Set up Claude Code

<Steps>
<Step title="Install and sign in">
Follow [Get started](/cli/index) to install the CLI and run `invopop auth login`. Make sure the default workspace is the one you want the agent to work in. For a first try, pick a sandbox.
</Step>
<Step title="Install the Invopop skill">
The CLI ships with a skill, a short set of instructions that teaches Claude Code how Invopop works and which commands to use. Install it with:

```bash
invopop skill install
```

This writes the skill into your Claude Code skills folder. Run it again after updating the CLI to pick up any changes.
</Step>
<Step title="Ask for something">
Open Claude Code and type `/invopop` followed by what you need. For example:

- "/invopop check whether invoice.yaml is valid and tell me what's wrong"
- "/invopop send the invoice in invoice.yaml through the Spain VERI\*FACTU workflow and tell me when it's done"
- "/invopop list the invoices we sent last month"

The agent runs the CLI, reads the JSON that comes back and explains it to you. When it isn't sure about a detail, the skill tells it to look it up in these docs rather than guess.
</Step>
</Steps>

<Tip>
You can read the skill yourself to see exactly what the agent is told. Run `invopop skill show` to print it.
</Tip>

## Other agents and tools

The skill is written for Claude Code, but nothing about the CLI is specific to it. Any assistant that can run terminal commands can use `invopop` in the same way. If you want to give such a tool the same guidance, print the skill with `invopop skill show` and paste it into the tool's instructions.

For agents that talk to the API directly rather than through the CLI, see the [agent primer](/llms) and the [AGENTS.md](https://docs.invopop.com/AGENTS.md) file.

## Good habits

- **Start in a sandbox.** Documents sent from a live workspace are real and may be legally binding. Keep the agent in a sandbox until you are confident in what it does.
- **Check the workspace.** Before asking for anything that creates or sends documents, have the agent run `invopop auth status`, or run it yourself, to confirm which workspace is active.
- **Review before sending.** Ask the agent to check a document with `invopop silo build` and show you the result before it runs a workflow.
- **A permission error is a stop sign.** If the agent reports a "403" or "not allowed" response, it means your account can't do that in this workspace. The skill tells the agent not to look for a way around it. Ask a workspace admin if you need the permission.
