The Invopop CLI is a small program you run in your terminal. It lets you do most of what the [Console](/console/index) does without opening a browser: check an invoice, send it through a workflow, look up a job, or reserve the next invoice number.

You don't need to be a developer to use it. If you can open a terminal and paste a line of text, you can use the CLI. It is also the easiest way to let an AI assistant such as Claude Code work in your workspace on your behalf. See [Use the CLI with AI agents](/cli/ai-agents).

<Info>
The CLI is open source at [github.com/invopop/cli](https://github.com/invopop/cli). Everything it does goes through the same public API that the Console uses, so it can only do what your account is allowed to do.
</Info>

## Install

<Tabs>
  <Tab title="macOS and Linux (Homebrew)">
    If you have [Homebrew](https://brew.sh), this is the simplest option. It also keeps the CLI up to date with the rest of your tools.

    ```bash
    brew install invopop/tap/invopop
    ```

    Homebrew builds the CLI from source the first time, so the install can take a minute. Later updates come with your usual `brew upgrade`.
  </Tab>
  <Tab title="Download a release">
    Download the file for your computer from the [releases page](https://github.com/invopop/cli/releases). Builds are available for macOS, Linux and Windows, on both Intel and ARM.

    Unpack it and move the `invopop` program somewhere on your `PATH`, for example `/usr/local/bin` on macOS and Linux.
  </Tab>
  <Tab title="Go">
    If you already have Go installed:

    ```bash
    go install github.com/invopop/cli/cmd/invopop@latest
    ```

    This puts an `invopop` program in your Go `bin` directory.
  </Tab>
</Tabs>

Check that it worked:

```bash
invopop --help
```

You should see the list of available commands. If the terminal says the command is not found, close and reopen it, or check that the install location is on your `PATH`.

## Sign in

Run the login command. It opens your browser so you can sign in with the same account you use for the Console.

```bash
invopop auth login
```

After signing in, the browser shows a short code. Paste it back into the terminal when asked. The CLI then lists the workspaces you belong to and asks which one to use by default.

<Tip>
Working over SSH or inside a container where the browser can't open? Add `--no-browser` and the CLI prints the sign-in link for you to open anywhere.
</Tip>

That's it. From now on every command runs in the workspace you chose, with the same permissions you have in the Console. The CLI keeps you signed in for a week and renews its access automatically, so you won't need to log in again for everyday use.

To see who you are signed in as and which workspace is active:

```bash
invopop auth status
```

To sign out:

```bash
invopop auth logout
```

<Accordion title="Using an API key instead of signing in">
If you prefer, or if you are setting up a script that runs without a person present, you can use an [API key](/console/api-keys) from the Console instead. Put it in the `INVOPOP_TOKEN` environment variable, or pass it with `--token` on each command.

```bash
export INVOPOP_TOKEN=YOUR_API_KEY
invopop ping
```

An API key already belongs to one workspace, so it cannot be combined with workspace switching. If both a sign-in and an API key are present, the API key wins.
</Accordion>

## Your first command

Check that the CLI can reach Invopop:

```bash
invopop ping
```

Then list the most recent documents in your workspace:

```bash
invopop silo entries list --limit 5
```

Results always come back as JSON, the same structure you see in the API reference. This makes them easy to read, copy into a support ticket, or pass to another tool.

## Switch workspaces

Most people only need one workspace, but if you belong to several, you can change the default at any time:

```bash
invopop auth workspace
```

You can also name the workspace directly. Use its slug for a live workspace, or `sandbox/` plus the slug for its sandbox, since both can share the same name:

```bash
invopop auth workspace my-company
invopop auth workspace sandbox/my-company
```

To run a single command in another workspace without changing your default, add `-w`:

```bash
invopop -w sandbox/my-company silo entries list
```

To see every workspace you belong to, with the exact name to use:

```bash
invopop access workspaces
```

<Note>
Sandbox and live workspaces use the same commands. The only difference is which workspace you point the CLI at, so be sure to check `invopop auth status` before doing anything in a live workspace.
</Note>

## Getting help

Every command explains itself. Add `--help` to any of them to see what it does and which options it accepts:

```bash
invopop silo entries create --help
```
